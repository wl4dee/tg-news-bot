Прожени повний пайплайн збирача без жодного запису назовні й доповідай про стан.

## 1. Інваріант «автопублікації не існує»

Спершу, до запуску, переконайся що жоден Python-файл не має доступу до каналу:

```bash
python -m tests.check_invariants
```

Перевірка йде по AST, а не грепом: у коді є коментарі, які самі згадують
`CHANNEL_ID` і `getUpdates`, щоб пояснити заборону, і греп на них спрацьовував би
щоразу. Ненульовий код виходу — це справжнє порушення. Зупинись, скажи про це
першим рядком і не продовжуй прогін.

Заразом прожени калібрувальний набір дедупу:

```bash
python -m bot.dedupe --selftest
```

## 2. Прогін

```bash
DRY_RUN=1 python -m bot.main
```

Секрети беруться з `.env`, якщо він є (він у `.gitignore`). Якщо змінних немає —
скрипт скаже, яких саме, і це нормальний результат для чистої машини.

## 3. Що перевірити у виводі

- Обидва Google Docs завантажились. Якщо `401`/HTML замість тексту — доступ до
  документів не відкритий, див. пункт 7 чекліста запуску. Це найчастіша причина.
- Скільки джерел опитано, скільки впало. Мертві джерела мають бути `warning`,
  а не трейсбеком.
- Скільки айтемів відсіяв дедуп, скільки пішло в Gemini (має бути ≤ ліміту
  `_candidates` з документа 02).
- Скільки чернеток пройшло ліміти рубрик і глобальний `_total`.
- Кожна чернетка надрукована повністю: рубрика, score, HTML-текст, `source_url`.

## 4. Доповідь

Коротко, без переказу логу:

- скільки айтемів на вході → скільки на виході, і де саме відсіялось
- список мертвих джерел, якщо є
- чи всі HTML-тексти валідні для Telegram (`bot/publish.py::validate_html`)
- що конкретно зламано, якщо зламано

Якщо все пройшло — скажи одним рядком і покажи рубрики та score чернеток таблицею.
