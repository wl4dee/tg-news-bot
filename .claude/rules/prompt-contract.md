# Контракт моделі

Контракт тримається у **трьох** місцях і мусить збігатися:

1. `config/prompt.md`, розділ «ФОРМАТ ВІДПОВІДІ»
2. цей файл
3. `bot/generate.py` (парсер) і `bot/main.py` (споживач полів)

Змінюєш одне — одночасно міняй усі три. Інакше модель повертатиме поле, якого
код не читає, або код чекатиме поле, якого модель не віддає.

## Що йде в модель

Один виклик на один айтем. Контекст:

| Блок | Вміст |
|---|---|
| системний | повний текст `config/prompt.md`, як є, без обрізань |
| `RAW_ITEM` | `{rubric, weight, source_type, source, title, text, url, published_at}` |
| `RECENT_POSTS` | до 30 останніх із `state.published`: `{message_id, story_key, topic, ts}` |

`RECENT_POSTS` потрібен рівно для одного: щоб модель зібрала блок «Раніше:» і не
переказала новину, яка вже виходила. Це головна фішка каналу — не викидай цей блок
заради економії токенів.

## Що модель повертає

Тільки JSON. Без ` ``` `, без пояснень до чи після.

```json
{
  "publish": true,
  "score": 8,
  "story_key": "bitmart-insolvency",
  "rubric": "крипта",
  "template": "Б",
  "text": "<HTML для Telegram>",
  "source_url": "https://...",
  "earlier_ids": [30912, 30905]
}
```

| Поле | Тип | Обов'язкове | Примітки |
|---|---|---|---|
| `publish` | bool | так | `false` → пропуск, решта полів ігнорується |
| `score` | int 1-10 | при `publish=true` | `config/prompt.md` велить не публікувати `< 6` |
| `story_key` | str | при `publish=true` | стабільний kebab-case, ключ ланцюжка історії |
| `rubric` | str | ні | одна з рубрик `config/sources.txt`; якщо модель не повернула — береться рубрика джерела |
| `template` | str | ні | `А` / `Б` / `В` / `Г`, суто для статистики |
| `text` | str | при `publish=true` | готовий HTML, ≤ 4096 |
| `source_url` | str | при `publish=true` | першоджерело, не ТГ-посередник |
| `earlier_ids` | int[] | ні | `message_id` попередніх постів, до 4 |

Відмова: `{"publish": false, "reason": "..."}`. Поле `reason` йде в лог і більше
нікуди — але воно корисне, коли калібруєш поріг.

## Правила парсингу (`bot/generate.py`)

- Запит іде з `generationConfig.response_mime_type = "application/json"`, тож
  огорожі бути не має. Захисне зрізання ` ``` ` усе одно робимо — моделі бувають
  креативними.
- **JSON не розібрався → залогувати сирий вивід (обрізаний до 500 символів) і
  пропустити айтем.** Не падати, не ретраїти, не намагатись «полагодити» JSON.
  Один зіпсований вивід не має валити прогін із 12 айтемів.
- Немає обов'язкового поля при `publish=true` → те саме: лог + пропуск.
- `rubric` обов'язковою НЕ є. Вона вже відома з `config/sources.txt`, бо задана
  поруч із джерелом; модель може її перекрити, коли новина насправді про інше.
  Вимагати її від моделі означало б відкидати цілком нормальні пости — на цьому
  вже обпеклись.
- `score` поза 1-10 → затиснути в межі, не відкидати.
- `text` довший за 4096 → айтем відкидається з логом. Не обрізаємо: обрізаний
  HTML — це зламані entities і `400` від Telegram.

## Чого модель не вирішує

Скільки постів вийде за прогін — вирішує **код**, за лімітами з
`config/sources.txt` (`_total`, ліміти рубрик). Модель оцінює кожен айтем ізольовано й не знає про
конкуренцію за слоти. Не перенось цю логіку в промпт.
