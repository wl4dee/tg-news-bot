# tg-news-bot

Telegram-канал новин (крипта / ринки / техно / Україна / Київ). Збирає матеріал із
RSS і публічних ТГ-каналів, переписує його Gemini у фірмовому стилі й публікує
**тільки після натискання кнопки ✅ людиною**.

## Архітектура: два незалежні компоненти

```
              config/prompt.md + config/sources.txt
                            │ читаються щопрогону з репозиторію
                            ▼
  cron */30  ──►  ЗБИРАЧ (Python 3.11, GitHub Actions)
                     │  збір → дедуп → Gemini → чернетка в DRAFTS_CHAT_ID
                     │  KV: пише draft:<id>, читає та вичищає log:* / retry:*
                     ▼
                  state.json ──► коміт назад у репозиторій

  натискання кнопки ──► Telegram webhook ──► ВОРКЕР (Cloudflare Worker)
                                               │  copyMessage у CHANNEL_ID
                                               ▼  KV: пише log:<id> / retry:<id>
```

Розділення не косметичне. Вебхук і `getUpdates` взаємовиключні: після `setWebhook`
метод `getUpdates` мертвий назавжди. Тому збирач **ніколи не читає апдейти Telegram** —
усі апдейти йдуть виключно у воркер.

## Стек

Python 3.11 · `requests`, `feedparser`, `beautifulsoup4` · Gemini Flash API ·
Cloudflare Workers + KV · Telegram Bot API з `parse_mode=HTML`.

Без фреймворків, без БД, без Docker, без FastAPI.

## Конфіг живе поза кодом

Промпт стилю і список джерел — це два файли в репозиторії, читаються при
**кожному** запуску:

| Файл | Що це |
|---|---|
| `config/prompt.md` | документ 01 — стиль каналу, критерії оцінки, шаблони, JSON-контракт |
| `config/sources.txt` | документ 02 — джерела, ваги, ліміти рубрик |

**Ніколи не хардкодь у Python промпт, джерела чи ліміти рубрик.** Правка стилю —
це коміт у `config/`, а не зміна коду. Код чіпається тільки коли ламається механіка.

Редагувати можна трьома способами: Claude Code, веб-редактор GitHub із телефону,
або звичайний коміт.

Змінні `PROMPT_DOC_URL` і `SOURCES_DOC_URL` лишились як **необов'язкове
перекриття**: якщо задані — береться Google Doc, а файл ігнорується. Це аварійний
шлях. Якщо вони не задані, мережевих запитів за конфігом не робиться взагалі.

Формат файлу джерел:

```
tg    | crypto_hd            | крипта  | 2
rss   | https://example/feed | Україна | 2
limit | крипта               | 3
```

Поля: `тип | значення | рубрика | вага(1-3)`. Рядки з `#` — коментарі.
`limit | рубрика | N` — максимум постів цієї рубрики за прогін.
Службові псевдорубрики: `limit | _total | N` (усього за прогін),
`limit | _candidates | N` (скільки айтемів іде в Gemini).

## НЕ РОБИТИ

- **Не додавати автопублікацію.** Жоден шлях у Python не має права писати в
  `CHANNEL_ID`. Публікація існує рівно в одному місці — `worker/src/index.js`,
  і тільки у відповідь на `callback_query` від кнопки ✅.
- **Не переходити на `getUpdates`.** Ніякого polling, ніде. Рядка `getUpdates`
  у Python-коді бути не повинно взагалі. Див. `.claude/rules/telegram-api.md`.
- **Не міняти JSON-контракт моделі** без одночасного оновлення
  `.claude/rules/prompt-contract.md` і `config/prompt.md`. Контракт
  тримається в трьох місцях і має збігатися.
- **Не додавати БД, Docker, FastAPI чи будь-який веб-фреймворк.** Стан — це
  `state.json` плюс KV, і цього достатньо.
- **Не хардкодити промпт, джерела або ліміти.** Вони в `config/`.
- **Не видаляти повідомлення-чернетки.** На них тримається статистика.
- **Не чистити `stats`** у `state.json`. Це дані для калібровки оцінювача.

## DRY_RUN

`DRY_RUN=1` — весь пайплайн виконується, але нічого нікуди не відправляється:
`publish.py` і `kv.py` друкують у консоль те, що надіслали б, і повертають
фейкові id. `state.json` у цьому режимі не комітиться.
